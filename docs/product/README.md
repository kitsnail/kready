# 产品输入

> 维护者：人（产品经理）。Agent 只读取，不修改本目录内容。
> 作用：为每个开发切片提供需求来源与验收标准，Agent 据此拆解、实现与验证。

## 目录结构

| 文件 | 内容 |
|---|---|
| `backlog.md` | 需求清单，按优先级排列，每条一个 ID（`REQ-nnn`） |
| `acceptance.md` | 每个 REQ 的验收标准（可判定条目），按 REQ 编号对应 |
| `decisions.md` | 产品决策记录（范围、取舍、废弃、发布），每条带日期与决策人 |

## 需求条目模板

```markdown
### REQ-001 <一句话标题>

- 状态：待开始 / 进行中 / 待验收 / 已验收 / 已取消
- 背景：为什么要做（一两句）
- 期望结果：用户能做到什么
- 验收标准：可自动判定的条目，逐条列出
- 关联：规则 ID、PR、CHANGELOG 条目（由 Agent 回填）
```

## 与开发流程的关系

1. 人在 `backlog.md` 写入或调整需求，状态为「待开始」。
2. Agent 开始切片前，引用对应 REQ ID，并在 PR 描述中写明。
3. 涉及规则、期望值、检查逻辑的需求，Agent 先出方案，经人确认后实现（AGENTS.md 中的 B 类）。
4. 切片合入后，Agent 把 REQ 状态改为「待验收」，并在条目的「关联」中回填 PR 链接。
5. 人按验收标准确认，状态改为「已验收」。

## 边界

- 本目录只放产品层内容：要什么、为什么、怎么算做完。
- 技术设计放 `docs/design/`，规则草案放 `docs/rules/`，不放这里。
