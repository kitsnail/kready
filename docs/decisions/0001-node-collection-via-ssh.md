# ADR 0001：节点级检查通过 SSH 只读采集

- 状态：已接受
- 日期：2026-11-18

## 背景

规则中的节点检查（inotify、sshd 配置、内核自动升级等）需要读取节点本机状态，Kubernetes API 无法提供。

## 决定

1. **采集方式**：通过 SSH 对节点执行**白名单内的只读命令**，采集后判定。
2. **登录账号**：`root`。已确认。
3. **节点清单**：通过 `kubectl get nodes` 获取，取 `InternalIP`。已确认。
4. **权限提升**：因为使用 root 登录，需要 root 的检查（如 `sshd -T`）直接执行，不需要人工提权。

## 约束

1. **只读命令白名单**：命令清单写在规则包中，代码只执行清单内的命令。例如 `sysctl -n <key>`、`cat <file>`、`systemctl is-active <unit>`。禁止任意命令，禁止管道和重定向写入。
2. **禁止写操作**：不得执行写文件、改配置、重启服务、安装软件等命令。
3. **主机密钥校验**：必须校验 `known_hosts`，不得关闭 host key 检查。
4. **凭据不入库、不输出**：私钥只通过 ssh-agent 或用户指定的密钥路径使用。工具不读取私钥内容，不把凭据写入报告或日志。kubeconfig 同样不输出。
5. **超时与并发上限**：每个节点、每条命令都有超时。连接失败记为 ERROR，不影响其它节点。
6. **测试不连真实节点**：单元测试使用采集结果快照，不发起 SSH 连接，也不调用真实集群。

## root 账号的风险与控制

root 权限最大。白名单和只读约束是唯一防线，因此：

- 白名单校验必须有单元测试，覆盖"非白名单命令被拒绝"。
- 命令执行层只接收白名单 ID，不接收原始命令字符串。
- 报告中记录每条执行的命令 ID，便于审计。
- 后续若改用只读运维账号，只需替换登录账号，不改变白名单与判定逻辑。

## 影响

- `internal/` 新增采集层，对外只暴露"按白名单 ID 执行只读命令"的接口。
- 规则 schema 包含 `collect` 字段，声明命令 ID。
- 节点清单由 kubectl 获取，采集层不直接读取 kubeconfig 内容。
- 报告区分三种结果：PASS、FAIL、ERROR（采集失败）。

## 备选方案（未采用）

- 临时只读 DaemonSet：需要在集群中部署组件，违反"不改变集群"的边界。
- 运维机代理采集器：增加部署与维护成本，暂不采用。
