# 输出契约 v1

> 状态：草案。输出字段属于契约，变更须按 `versioning.md` 处理。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 结论为正常（WARN、INFO、工具未覆盖不影响退出码） |
| 1 | 结论为异常或未能确认 |
| 2 | 工具错误（参数错误、无适用规则、内部错误） |

## 结果状态

| 状态 | 含义 |
|---|---|
| `PASS` | 判定项符合期望 |
| `FAIL` | 判定项不符合期望，需处理 |
| `WARN` | 判定项不符合期望，但影响有限，输出为提醒，不改变结论 |
| `ERROR` | 判定项无法取得实际值。按 `source` 区分性质，见下 |
| `INFO` | 信息项，仅输出当前值，不判定 |
| `SKIP` | 不适用（如无对应角色节点） |

## ERROR 的性质（source）

ERROR 结果带 `source` 字段，说明其性质，决定它是否影响结论：

| source | 含义 | 是否影响结论 | 归属 |
|---|---|---|---|
| `collect` | 采集失败或数据不完整（SSH 失败、节点数据缺失、控制面版本缺失） | 是（使结论为未能确认） | 运行环境：检查节点连通性与凭据后重跑 |
| `tool-gap` | 工具在当前模式无数据来源（实时模式不采集 `config.*`）或规则配置错误 | 否 | 工具能力边界：用离线快照补充 |

## 结论

只描述集群，三种取值：

- `异常`：存在 FAIL，即确认不合规。
- `未能确认`：无 FAIL，但存在 `source=collect` 的 ERROR，无法确认集群状态。不得写成正常。
- `正常`：无 FAIL，且无 `source=collect` 的 ERROR。
- `tool-gap` 不进入结论。
- WARN 不改变结论，但在输出中单独列出。

## 规则包选择

- 以控制面节点的 kubelet 版本为基线选择规则包。`v1.36.4` → `2.32`。
- 控制面版本须唯一，且精确匹配某个规则包的 `applies_to`。
- 以下情形 → 退出码 2，输出"无适用规则"，不做判定：无控制面节点、控制面版本不一致、版本不在支持范围。
- 工作节点版本与基线不一致不属于无适用规则：由 `VER-01` 判 FAIL（退出码 1），列出不符合的节点。
- 工具不读取部署源文件，不做基线哈希校验。

## 问题说明

- FAIL、WARN、ERROR 结果附带两段说明，便于运维直接决策：
  - `impact`：影响，说明不处理会有什么后果。
  - `hint`：处理，给出可直接复制的命令或操作方向。
- 两段文字由规则提供，不由工具推断。字段保留为占位，具体取值与必填规则在实际问题中逐步细化。目的是辅助一线工程师判断决策，而非形式化输出；无实际价值的字段不保留。
- 处理命令须标明风险等级：只读查看、需重启、会改配置。

## JSON 结构

用 `--format json` 输出。`summary` 六个计数始终存在，未出现的状态为 0。


```json
{
  "schema_version": 2,
  "kready_version": "0.1.0",
  "pack": "2.32",
  "rules_rev": 2,
  "conclusion": "正常",
  "summary": { "pass": 0, "fail": 0, "warn": 0, "error": 0, "info": 0, "skip": 0 },
  "results": [
    {
      "id": "NODE-02",
      "status": "FAIL",
      "target": "cn-192-168-3-52",
      "actual": "128",
      "expect": "1280",
      "impact": "inotify 实例数不足，可能导致 kubelet 或容器无法创建监听",
      "hint": "只读查看：sysctl -n fs.inotify.max_user_instances"
    },
    {
      "id": "SYS-04",
      "status": "INFO",
      "target": "cluster",
      "actual": "3"
    }
  ]
}
```

- `conclusion`：`正常`、`异常` 或 `未能确认`。
- `target`：集群级为 `cluster`，节点级为节点名。
- `actual`：实际值，字符串。
- `expect`：仅 `judge` 项有，字符串。
- `impact`、`hint`：FAIL、WARN、ERROR 结果有，内容见"问题说明"。
- `ERROR` 结果增加 `error` 字段，内容为简短原因，不含凭据。

## 人类可读输出

- 第一行：结论。第二行：节点数（如实反映，不判定）。
- 分段按顺序输出，没有内容的段不显示：
  - `【必须处理】`：FAIL 结果。每条列出目标、实际、期望；规则提供时附影响与处理。
  - `【未能确认】`：`source=collect` 的 ERROR。附说明：请检查节点连通性与凭据后重新运行。
  - `【工具未覆盖】`：`source=tool-gap` 的 ERROR。附说明：不代表集群有问题，需用离线快照补充。同一原因的项合并为一行。
  - `【参考信息】`：INFO 结果。只陈述当前值。
- 每条以中文标题开头，ID 放括号中：`标题（ID）`。标题取自规则包的 `title`。
- 影响与处理取自规则包的 `impact`、`hint`。未填写时不显示，不输出占位。
- WARN 在输出中单独列出，格式同必须处理。

## 兼容规则

- 新增可选字段：`schema_version` 不变。JSON 结果新增 `title` 字段（可选），属于此类。
- 人类可读输出的行格式可以调整，不属于契约字段；脚本应读取 JSON。
- 删除、重命名字段，或改变状态与退出码含义：递增 `schema_version`，按 MAJOR 处理。
- 版本 2：结论新增取值“未能确认”，退出码 1 的含义扩展为“异常或未能确认”。按上条规则判为破坏性变更，`schema_version` 由 1 递增为 2。
- 版本历史：
  - 1：结论为正常/异常，ERROR 一律计为异常。
  - 2：结论为正常/异常/未能确认，ERROR 带 `source`（collect / tool-gap），tool-gap 不影响结论与退出码。
